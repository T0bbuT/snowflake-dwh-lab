# ADR-0006: 売上を数量と単価から再計算する

- ステータス: 採用
- 由来: 固有
- 決定日: 2026-10-04
- 記録日: 2026-10-04
- 事後記録: No

## 背景・課題

CRMの売上明細には、売上・単価の欠損、0以下の値、「売上 = 数量 × 単価」が成り立たない行が含まれる。2026-10-04時点のCSV（60,398行）の内訳は次のとおり。

| 売上 / 数量 / 単価 | 行数 | 例 |
| --- | ---: | --- |
| 売上と数量×単価が一致しない | 10 | 35 / 2 / 35 |
| 売上がNULL | 8 | NULL / 1 / 9 |
| 単価がNULL | 7 | 10 / 2 / NULL |
| 単価が負 | 5 | 769 / 1 / -769 |
| 売上が負 | 3 | -18 / 1 / 9 |
| 売上が0 | 2 | 0 / 1 / 10 |

数量の欠損・0以下はない。

元教材のSilverロードは、売上と単価の一方からもう一方を補正する。売上が欠損・0以下・数量×単価と不一致なら数量×|単価|で置き換え、単価が欠損・0以下なら売上÷数量で補う。この方式をSnowflakeへ移したところ、次の問題があった。

- 単価が0で売上が正しい行では、売上が数量×0 = 0で上書きされ、補完した単価と矛盾する。
- 売上が欠損し単価が負の行では、売上は補えるが、単価は欠損した売上から計算されるためNULLになる。
- 売上と単価の両方を補えない行では、入力の組み合わせによりNULL・0・負の値が混在する。
- 単価を売上÷数量で補うと、T-SQLの整数除算（切り捨て）とSnowflakeの除算（INT列への格納時に四捨五入）で結果が異なり得る。
- 同じSELECT内で列名と同名の別名を付けた場合、他の式からは元の列が参照されるため、単価の補完には補正前の売上が使われる（2026-10-04に実機で確認）。

これらを個別に修正する案も検討したが、売上を正とすべき場合と単価を正とすべき場合を判断する業務情報がない。本プロジェクトのCSVはダミーデータであり、元システムの仕様からどの値が正しいかを推定することもできない。

## 決定事項

売上・数量・単価を次のとおり変換する。売上はソースの値を使わず、変換後の数量と単価から計算する。

| 列 | ソースの値 | 変換後 |
| --- | --- | --- |
| 数量 | 正 | そのまま |
| 数量 | 0・負・NULL | NULL |
| 単価 | 正 | そのまま |
| 単価 | 負 | 絶対値（符号の誤りとみなす） |
| 単価 | 0・NULL | NULL |
| 売上 | （値を問わない） | 変換後の数量 × 変換後の単価。どちらかがNULLならNULL |

Silverでは行を削除せず、受注番号・商品・顧客・日付・変換後の値を保持する。Goldの `FACT_SALES` では、売上がNULLの行（数量または単価がNULLの行）を除外し、分析に使える行だけを提供する。

## 検討した選択肢

### 元教材と同じく売上と単価を相互に補完する

上記の問題を個別に修正する必要がある。さらに、数量・売上の符号（返品・キャンセルの可能性）や、数量を補完する場合の端数の扱いなど、データから判断できない業務ルールが増えるため採用しない。

### 単価が欠損した行は、売上÷数量で単価を補う

現在のCSVの7行で売上を残せる。一方で「通常は単価を正とするが、単価がない場合は売上を正とする」という例外が生じるため採用しない。

### 数量が負の行を返品・キャンセルとして保持する

返品・キャンセルを表すという前提を裏付ける情報がないため採用しない。

## 影響

- 売上と数量×単価が常に一致し、相互補完による矛盾や除算の端数処理の問題がなくなる。
- 単価が欠損したソースの売上は使われない。2026-10-04時点のCSVでは7行の売上・単価がNULLになり、Goldの `FACT_SALES` から行ごと除外される。そのため `FACT_SALES` の件数はSilverの売上明細より少なくなり、注文数・数量の集計にもこれらの行は含まれない。
- 数量・単価のいずれかが変換後にNULLとなった行は、Silverの品質チェックで確認対象として抽出される。行が返ることは仕様どおりであり、不具合とは判断しない。
- それ以外の行は、元教材の補正と同じ結果になる。

## 見直し条件

- 売上・数量・単価のどれが正しいかを判断できる業務情報が得られた場合
- 負の数量を返品・キャンセルとして扱う要件が生じた場合
- 売上がNULLとなる行が増え、分析に影響する場合
