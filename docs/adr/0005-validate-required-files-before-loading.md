# ADR-0005: 必須CSVをロード開始前に検証する

- ステータス: 採用
- 由来: 固有
- 決定日: 2026-09-21
- 記録日: 2026-09-23
- 事後記録: Yes

## 背景・課題

Bronzeは6つのCSVから6つのテーブルを順番に全件入れ替える。必要なファイルが不足した状態でロードを開始すると、先に`TRUNCATE`したテーブルだけが更新され、既存データを失う可能性がある。

CSVのアップロードとロードは別の操作であり、配置漏れ、配置先の誤り、ファイル名の誤りが起こり得る。また、ステージのディレクトリテーブルは、直前の`PUT`や`REMOVE`をまだ反映していない可能性がある。

## 決定事項

`LOAD_BRONZE()`は、最初の`TRUNCATE`より前に次の事前検証を行う。

1. `ALTER STAGE ... REFRESH`でディレクトリテーブルを更新する。
2. 必須6ファイルの相対パスを完全一致で確認する。
3. 一つでも不足していれば、不足パスを含む`ERROR`を返し、Bronzeテーブルを変更せず終了する。
4. 各`COPY INTO`でも`FILES`に完全な相対パスを指定する。

## 検討した選択肢

### 手順書でのLIST確認だけに任せる

手動確認の漏れから既存データを保護できないため、プロシージャ自身でも検証する。

## 影響

- 必須CSVの不足時は、既存の全Bronzeテーブルを保持できる。
- `.csv.bak`などの似た名前を必須ファイルとして誤認しない。
- 不足ファイルを戻り値とEvent Tableのログから確認できる。
- 過去に配置した古いCSV、空ファイル、列構造や内容の不備は検出できない。
- 検証と`COPY INTO`の間にファイルが変更される競合は防げない。
- ロード開始後のエラーに対する、6テーブル全体の原子性は保証しない。

## 見直し条件

- ファイルの更新日時、ハッシュ、行数、スキーマも受け入れ条件に含める場合
- 複数テーブルのロードを原子的に公開する必要がある場合
- 外部オーケストレーターでファイル到着とロードを管理する場合
